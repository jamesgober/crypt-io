# v1.7.0 — Pure-Rust OTP

**Release date:** 2026-11-20
**Status:** stable minor release. No API change and no change to any
output: every code, tag, ciphertext and stream is what 1.6.0 produces.
MSRV stays 1.85.

---

## What this release is

Two changes, both internal.

- **The `otp` feature is pure Rust.** HOTP, TOTP and
  `hmac_sha1_legacy` used AWS-LC for HMAC-SHA1, which made two-step
  sign-in need a C compiler (and NASM or `prebuilt-nasm` on Windows)
  even in builds that use nothing else from AWS-LC. They now run on
  crypt-io's own HMAC, the one behind `mac-hmac`, over the RustCrypto
  `sha1` crate. `otp` builds anywhere Rust does, musl included.
- **Constant-time comparison is much faster.** `Tag` equality, the
  HMAC `*_check` functions and the OTP checks share one compare. It
  XORs the inputs 8 bytes at a time, ORs the results into one
  accumulator and decides with a single `subtle` comparison, so a
  16-byte tag compares in a few nanoseconds instead of about 50.

```toml
[dependencies]
crypt-io = { version = "1.7", features = ["otp"] }   # no C compiler needed
```

## Same codes

HMAC-SHA1 is pinned by:

- RFC 4226 appendix D (codes and the HMAC-SHA1 intermediates),
- RFC 6238 appendix B, the SHA-1 rows through the public API, and the
  SHA-256 and SHA-512 rows through the same truncation code,
- RFC 2202 section 3 (keys shorter than, equal to and longer than the
  64-byte block),
- a test against AWS-LC's HMAC-SHA1 for keys of 0 to 200 bytes and
  messages of 0 to 299 bytes, when a `sign-*` feature brings AWS-LC in,
- the `otp_check` fuzz target, which now also compares
  `hmac_sha1_legacy` with AWS-LC on every input.

CI fails if any feature set without `sign-*` or `aead-aws-lc` pulls
AWS-LC.

## Performance

1.6.0 and 1.7.0 linked into one binary, alternating batches, median of
41 rounds, three repeats. Windows 11, Rust 1.99, release with fat LTO,
on a busy machine.

| Case | 1.6.0 | 1.7.0 | Faster |
|---|---:|---:|---:|
| `Tag<16> == [u8; 16]` | 49 ns | 3.2 ns | 15× |
| `Tag<32> == [u8; 32]` | 96 ns | 3.2 ns | 30× |
| `Tag<64> == [u8; 64]` | 200 ns | 3.4 ns | 58× |
| `otp::totp` | 222 ns | 121 ns | 1.8× |
| `otp::totp_check`, window 1 | 595 ns | 346 ns | 1.7× |
| `otp::hmac_sha1_legacy`, 64 B | 241 ns | 140 ns | 1.7× |

The compare's cost no longer grows with the tag: what is left is the
one `subtle` barrier. Equal and unequal inputs take the same time. OTP
got faster too: AWS-LC's HMAC key setup cost more than RustCrypto's
SHA-1 on a short message.

## Verification

- Local gates before push: fmt, clippy for every CI feature set, tests,
  doctests and docs with warnings denied, on Rust 1.99 and MSRV 1.85
  on Windows and on stable and 1.85 on Linux (163 checks each),
  including a check that no feature set without `sign-*` or
  `aead-aws-lc` pulls AWS-LC.
- 390 tests pass with all features (205 unit, 129 integration, 56
  doctests).
- `cargo semver-checks` against 1.6.0, default and all features: no
  semver change needed.
- Lockfiles resolved as committed, for Rust 1.85, for 1.86 and newest:
  no `ctutils` in any, `sha1` 0.11.0, `cargo audit` clean.
- Miri: the CI subsets with `preset-all`, plus the OTP, compare and
  `Tag` tests.
- Fuzzing: `otp_check` (with the AWS-LC comparison) about 24.9 million
  runs and `mac` about 4.4 million runs, 180 seconds each, no findings.
- The compare's x86-64 code was read: straight-line XOR and OR, one
  `subtle` barrier, no branch on the data.

## Upgrading

```toml
[dependencies]
crypt-io = "1.7"
```

No code change. Builds that enabled `otp` together with
`prebuilt-nasm` only for OTP can drop `prebuilt-nasm`.
