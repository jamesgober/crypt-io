# v1.6.0 — Review Fixes

**Release date:** 2026-11-11
**Status:** stable minor release. No wire-format change: ciphertexts,
sealed buffers and streams are byte for byte what 1.5.0 writes and
reads. MSRV stays 1.85. No new third-party dependency. A few default
limits on untrusted input are tighter (listed below, with the setting
that restores the old behaviour).

---

## What this release is

An independent review of 1.5.0 (security, performance, code quality)
found no break in the cryptography, and a set of smaller things worth
fixing: default cost limits that were too generous for hostile input,
plaintext copies left in freed memory by the file helpers, per-call key
setup on hot paths, and documentation that had drifted from the code.
1.6.0 fixes all of them. Every fix has a regression test that fails on
1.5.0.

```rust
use crypt_io::Crypt;

let keyed = Crypt::new().keyed(&key)?;        // key set up once
let ct = keyed.encrypt(b"record")?;           // same bytes as Crypt::encrypt
let pt = keyed.decrypt_zeroizing(&ct)?;       // wiped on drop
```

---

## Faster AEAD

- **`Crypt::keyed(key)` returns a `KeyedCrypt`.** Every `Crypt` call
  sets the key up again (AES key expansion and the GHASH key, or the
  ChaCha20 key). A `KeyedCrypt` does it once. Its methods are `Crypt`'s
  without the key argument and produce the same bytes. Its `open`
  accepts only buffers sealed under its own algorithm, for callers that
  want to pin the algorithm on the read side.
- **Feature `aead-aws-lc`.** ChaCha20-Poly1305 and AES-256-GCM run on
  AWS-LC (already used by the `sign-*` features) instead of RustCrypto.
  The output is standard AEAD bytes; tests run both engines against each
  other and against every RFC and NIST known-answer test, and the
  frozen stream test vectors pass on both. XChaCha20-Poly1305 stays on
  RustCrypto. It needs a C compiler (and NASM or `prebuilt-nasm` on
  Windows x86-64), so it is off by default.
- The stream types set their key up once per stream instead of once per
  chunk.

Measured against 1.5.0 in one binary, alternating, median of 41 rounds,
three repeats (details in `docs/PERFORMANCE.md`). Above 1.0 means 1.6.0
is faster.

| Case | 64 B | 1 KiB | 16 KiB |
|---|---|---|---|
| `Crypt`, default build, every algorithm | 0.95 – 1.03 | 0.97 – 1.07 | 0.97 – 1.05 |
| `KeyedCrypt` AES-256-GCM, default build | 1.78 – 1.93 | 1.15 – 1.18 | 0.99 – 1.06 |
| `Crypt` ChaCha20-Poly1305, `aead-aws-lc` | 3.75 – 4.69 | 2.86 – 3.03 | 2.12 – 2.24 |
| `KeyedCrypt` AES-256-GCM, `aead-aws-lc` | 1.87 – 2.43 | 2.26 – 2.62 | 2.49 – 2.96 |
| `Crypt` AES-256-GCM encrypt, `aead-aws-lc` | 0.85 – 0.89 | 1.52 – 1.60 | 2.40 – 2.63 |

Streams of 1 MiB run 1.5 to 2.3 times faster with `aead-aws-lc`. One
trade-off: AWS-LC's AES key setup is slower, so a one-off 64-byte AES
encrypt is about 12% slower with the feature on; `KeyedCrypt` avoids
it. Allocations per call are unchanged.

## Tighter limits on untrusted input

| What | 1.5.0 | 1.6.0 | To get the old behaviour |
|---|---|---|---|
| Argon2 memory in a checked hash (default policy) | 1 GiB | 256 MiB | `Argon2Policy::new().with_max_cost(m, t, p)` |
| Argon2 memory times passes (default policy) | no cap | 1 GiB-pass | `with_max_cost` sets it to `m * t`; or `with_max_work` |
| `argon2_hash_with_params` | any parameters | must pass `Argon2Params::validate` | `argon2_hash_with_policy` |
| PBKDF2 limit | iterations | iterations times 32-byte output blocks | none needed for 32-byte outputs |
| `StreamDecryptor::new` | reserved one chunk (up to 16 MiB) | reserves nothing; grows with input | |
| COSE Ed25519 key of small order | accepted | refused | `Ed25519PublicKey::from_bytes` still accepts it |

Argon2 at the new default ceiling takes under a second on the
reference machine (1.5.0's ceiling allowed far longer). Servers
that check hashes from an untrusted store should still set caps no
higher than their own hashing parameters.

## Less plaintext left in memory

- `stream::encrypt_file` and `decrypt_file` read and write through
  their own buffers, which they wipe on every exit. Before, the
  `BufReader` / `BufWriter` buffers they used were freed with file
  plaintext still in them. A test scans every freed heap block for the
  plaintext.
- New forms that return a type wiped on drop:
  `kdf::hkdf_sha256_zeroizing`, `kdf::hkdf_sha512_zeroizing`,
  `StreamDecryptor::update_zeroizing`, `finalize_zeroizing`,
  `KeyedCrypt::decrypt_zeroizing`.
- `preset-minimal` now includes `zeroize`, so wiping stays volatile in
  the smallest preset. CI also tests a feature set without `zeroize`.

## Documented, not changed

- **ECDSA P-256 signatures are not unique.** `(r, n - s)` checks
  whenever `(r, s)` does, as in every mainstream library. Never use
  signature bytes to detect replays; use the challenge and the passkey
  signature counter.
- **Ed25519 small-order keys.** `Ed25519PublicKey::from_bytes` keeps
  accepting them, as RFC 8032 allows; the passkey path refuses them.
- **OTP secrets must be at least 128 bits** (RFC 4226). Older 80-bit
  enrolments are refused on purpose; re-enrol those users.
- **`mac::hmac_sha256` and friends return `Result`** although they
  cannot fail. Changing that breaks every caller, so it waits for 2.0.
- `PERFORMANCE.md`, `SECURITY.md`, the crate docs and `rng.rs` were
  checked against the code and corrected where they had drifted.

## Verification

- Local gates before push: fmt, clippy with every feature set, tests,
  doctests and docs with warnings denied, on Rust 1.99 and MSRV 1.85,
  on Windows (139 checks) and Linux (138 checks).
- 386 tests pass with all features (unit, integration and doctests).
- `cargo semver-checks` against 1.5.0: no semver break.
- `cargo audit`: no advisories against runtime dependencies.
- Fuzzing: `argon2_parse`, `stream_decrypt`, `aead_decrypt` and
  `cose_key`, 120 seconds each, about 7.7 million runs, no findings.
- Performance: 1.5.0 and 1.6.0 linked into one binary, alternating
  batches, median of 41 rounds, three repeats.

## Upgrading

```toml
[dependencies]
crypt-io = "1.6"
```

Most callers need no change. Check these:

- Code that hashes with tiny Argon2 parameters (tests) through
  `argon2_hash_with_params`: switch to `argon2_hash_with_policy`.
- Stored Argon2 hashes above 256 MiB, or above 1 GiB-pass of memory
  times passes: check them with `argon2_check_with_policy` and a
  policy that allows them.
- PBKDF2 with long outputs near the iteration cap: the cap now counts
  every 32-byte block.
